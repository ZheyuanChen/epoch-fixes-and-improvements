\begin{abstract}
This register identifies selected bug fixes and modest numerical or usability improvements in \href{https://github.com/ZheyuanChen/epoch_dev}{\code{epoch_dev}}, and asks a precise question for each: is the correction present in the official \href{https://github.com/epochpic/epoch}{EPOCH} \code{main} branch? It includes the laser absorption diagnostic fix merged through \pr{896} and the exact nonlinear Breit--Wheeler (NBW) rate tables in the fork. It is an inventory of source changes, not a claim that all fork features have been proposed upstream.
\end{abstract}

\section{How status was checked}

The official \code{main} tip was \official{f294c484f76dff0777d5cc0d50b38506a2b049ff} on 30 October 2026 (\code{git ls-remote} against \code{epochpic/epoch}). The audited fork tip was \fork{b908c85911b314f6e07ed9a31caf0396612ffd83} on \code{spin}. ``Yes'' means the upstream merge commit is an ancestor of official \code{main}. ``No'' means the relevant fork commit is not an ancestor and the named table, switch, guard, or algorithm is absent from the official \code{main} source at that tip. A merge into \code{4.20-devel} alone is \emph{not} counted as present in \code{main}. Other official development branches are mentioned only where their status was separately checked.

The scope is substantive source fixes and small improvements visible in the fork history. Major new physics packages and uncommitted prototype code are outside this register. Dimensions refer to the implementation at the cited fork commit; they do not imply equivalent support in the other dimensions. These are source and history checks, not fresh EPOCH simulation results.

\section{Two upstream merges that require different labels}

\paragraph{Laser absorption, already on \code{main}.}
Tom Goffrey merged \pr{896} into \code{4.20-devel} on 10 April 2026 as \official{0984b1d31}. The patch corrects the sign of injected energy at \code{x_max}, \code{y_max} and \code{z_max}; the previous negative energy could give a zero absorption coefficient (\issue{893}). The merge is an ancestor of official \code{main} and is listed in the \href{https://github.com/epochpic/epoch/releases/tag/v4.20.1}{v4.20.1 release notes}. No fork-only fix remains to upstream for this item.

\paragraph{Photon-probe IDs, merged to development but absent from \code{main}.}
\pr{906} merged \official{241d6fb9c} into \code{4.20-devel} on 1 June 2026, after the current official \code{main} tip. In the fork, \fork{3e4734522} moves the 2D photon ID collective call ahead of the empty-rank return and additionally fixes ID counter persistence across restarts and file-based particle loading. The official PR and the fork commit are related but \emph{not equivalent in scope}; the latter's restart/file-ID changes should be reviewed separately.

\section{Numerical and QED improvements in the fork}

\paragraph{NBW tables.}
Official \code{main} reads \code{pairprod.table}; the 2D fork adds \code{pairprod_lcfa.table} and the \code{pair_tables = legacy | lcfa} selector. The legacy rate uses Erber's approximate analytic expression; \code{lcfa} selects a numerically tabulated locally constant field approximation (LCFA) rate. The fork also provides parallel/perpendicular NBW energy-split tables. With spin QED off, \code{legacy} keeps the old rate and \code{energy_split.table}, while \code{lcfa} selects the LCFA rate and unpolarised split. With spin QED on, \code{lcfa} is the default, and \code{legacy} restores only the old rate; the spin-resolved split remains. This changes physics results, so published runs should record the selector and table hashes. The generator scripts for these tables are currently untracked in the local source tree; the committed tables and reader are present, but clean-checkout regeneration has not been demonstrated here.

\paragraph{NLCS sampling and time stepping.}
The 2D fork adds spin-resolved NLCS quantile tables and a switch to use the previous lookup. It also adds a sub-step no-transition update. Neither is part of official \code{main}; these affect spin-aware QED paths and should not be described as global corrections to every EPOCH emission mode. The legacy \code{ksi_sokolov.table} remains relevant to spin-off runs.

\paragraph{Radiation reaction.}
The 2D fork's \code{use_full_landau_lifshitz}, \code{gaunt_factor} and \code{rr_midpoint} options supplement EPOCH's original reduced force and explicit kick. Defaults preserve the old branch behaviour; enabling these options changes the physical model or time integration. There is no 3D implementation of this fork change in the audited \code{spin} branch.

\section{Correctness fixes and operational limits}

The Higuera--Cary correction is in all three fork dimensions and in a separate fork branch based on \code{4.21-devel} (\fork{2684956bf}); it is absent from official \code{main}. The fork also guards trident pair creation when pair production is disabled, fixes a multi-photon-species NBW argument in 2D, restores 2D spin state on restart and warns about explicit charge/mass values replaced by \code{identify}. These items should be considered independently of the larger spin and pair-boost features.

The pair-boost group in Table~\ref{tab:status} spans distinct corrections: Breit--Wheeler boost handling (\fork{3e9f3121f}), muon gamma sampling (\fork{fbb9a9459}), Bethe--Heitler scaling in 3D and then 1D/2D (\fork{92552de69}, \fork{a5716caf2}), and additive optical depths (\fork{99ce3c685}). The table's single row is a tracking convenience, not one patch to cherry-pick.

The custom laser reader has several fork-local corrections: half-cell sampling, MPI-safe file loading, independent storage per laser block and continuous 3D re-slabbing. Official \code{main} does not contain the custom-file reader, so these are improvements to a fork feature rather than regressions of stock EPOCH. The upstream \href{https://github.com/epochpic/epoch/issues/910}{custom-profile issue \#910} was open at the check date; an issue is not an upstream merge.

\section{Maintaining this register}

For each future entry, record the symptom, affected dimensions, fork commit, official PR or issue (if any), \code{main} tip checked, an implementation-level test, and whether the change affects numerical results. Refresh the upstream status after each official release or merge; do not infer \code{main} inclusion from a development-branch PR badge. The command-level method and known limitations are in the accompanying \code{README.md}.
