\section{Purpose and status convention}
This is a shared register of EPOCH bugs and incremental improvements. It starts
with the official \href{https://github.com/epochpic/epoch}{EPOCH} source and
records whether each change is in official \code{main}. An implementation in
\href{https://github.com/ZheyuanChen/epoch_dev}{a separate fork} is identified
explicitly; it does not by itself make an upstream issue fixed. The register
is selective, and contributors are welcome to add independently verified
issues from any part of EPOCH.

The official \code{main} tip checked here is
\upcommit{f294c484f76dff0777d5cc0d50b38506a2b049ff}. The statuses mean:
\textbf{Fixed}---the correction is in that \code{main} history;
\textbf{Dev only}---it is in an official development branch but not
\code{main}; \textbf{Open}---the stated stock-code behaviour remains in
\code{main}; \textbf{Baseline}---an existing method works as designed but
has a documented alternative; \textbf{N/A}---the affected feature exists
only in the fork, so this is not a stock EPOCH bug. Statuses are source
assessments at the stated commit, not fresh simulation results.

\section{Registry}

mark fork-only features. To add an item, copy one
\code{\RegistryRow} line in \code{registry.tex} and add a matching labelled
entry in \code{items.tex}; the title column wraps automatically.

\section{Adding and updating entries}
Use the short table row for discovery, and keep reproduction steps, source
paths, links, affected dimensions and validation in the corresponding
detailed item. For a serious defect, use a \code{\subsection} and, if useful,
\code{\subsubsection} headings. Give fork-specific additions an F ID and
state which feature is absent from stock EPOCH. Do not mark an item
\textbf{Fixed} merely because a PR was merged to a development branch.
Record the official \code{main} commit and check date whenever a status
changes. A copyable example and the build instructions are in
\code{CONTRIBUTING.md}.
